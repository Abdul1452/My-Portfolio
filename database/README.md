# Database - PostgreSQL + Prisma

## Structure

```text
backend/prisma/
├── schema.prisma          # THE schema — the only place tables are defined
└── migrations/
    ├── 0_init/            # Baseline, generated by Prisma from schema.prisma
    └── migration_lock.toml

database/
└── seeds/                 # Starter data, inserted through the Prisma client
    ├── seed.ts
    ├── projects.seed.ts
    └── skills.seed.ts
```

The Prisma schema lives at `backend/prisma/schema.prisma`. Keeping it inside
`backend/` lets Prisma and pnpm resolve `@prisma/client` from the backend
package instead of trying to auto-install it from the repository root.

## No hand-written SQL

The project used to keep the schema in two places: Prisma models *and* raw
`.sql` files. They drifted apart (different defaults, different delete rules),
so the SQL files were removed. `schema.prisma` is now the single source of
truth, and Prisma writes every migration.

### Changing the schema

1. Edit the model in `backend/prisma/schema.prisma`
2. Run `pnpm db:migrate` and give the migration a name when prompted
   (e.g. `add_project_tags`)
3. Prisma creates `backend/prisma/migrations/<timestamp>_<name>/migration.sql`,
   applies it to your local database, and regenerates the client
4. Commit the schema change and the new migration folder together

### The one exception: CHECK constraints

Prisma has no syntax for CHECK constraints, so the two we use are appended by
hand to the end of `0_init/migration.sql`:

| Constraint | Rule |
|---|---|
| `projects_category_check` | `category` must be `'engineering'` or `'pm'` |
| `skills_percentage_check` | `percentage` must be between 0 and 100 |

To add another, run `pnpm --filter backend exec prisma migrate dev --create-only`,
add the `ALTER TABLE ... ADD CONSTRAINT ... CHECK (...)` line to the generated
file, then run `pnpm db:migrate` to apply it.

## Commands

```bash
# From the repository root:
pnpm db:generate     # Re-generate Prisma client after schema changes
pnpm db:migrate      # Apply Prisma migrations
pnpm db:seed         # Populate with initial data
pnpm db:studio       # Open visual DB browser at localhost:5555
```

### Database created before the Prisma baseline?

If your local database was set up from the old migrations
(`20260727190000_init`, `20260730132603_init_check`), Prisma will report that
those migrations are missing. Local data is only seed data, so reset it:

```bash
pnpm --filter backend exec prisma migrate reset   # drops, re-migrates, re-seeds
```
